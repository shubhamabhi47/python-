Yes — the confusing part is that **the class `Inner` is already defined by the time `Outer.__init__()` runs**.

Look at the order Python follows:

```python
class Outer:
    class Inner:
        def show(self):
            print("Inner object belongs to Outer")

    def __init__(self):
        self.inner = self.Inner()
```

When Python executes `class Outer:`, it first creates the `Outer` class. During that process, it creates the nested `Inner` class too.

So by the time you do:

```python
outer = Outer()
```

Python calls:

```python
Outer.__init__(outer)
```

and inside it:

```python
self.inner = self.Inner()
```

Here:

* `self` → the `outer` object
* `self.Inner` → the `Inner` class
* `self.Inner()` → creates an `Inner` object
* `self.inner = ...` → stores that `Inner` object inside `outer`

So conceptually:

```text
Outer class
   │
   ├── Inner class
   │
   └── __init__()

        ↓ outer = Outer()

outer object
   │
   └── inner ───────→ Inner object
                         │
                         └── show()
```

### But what about the order in your original code?

You wrote:

```python
class Outer:
    def __init__(self):
        self.inner = self.Inner()

    class Inner:
        def show(self):
            print("Inner object belongs to Outer")
```

You might think:

> "`__init__` appears before `Inner`, so how can it know about `Inner`?"

The key is that **Python does not execute the body of `__init__` when it defines the function**.

When Python sees:

```python
def __init__(self):
    self.inner = self.Inner()
```

it essentially says:

> "Okay, I'll create this function. I'll execute its code later when an `Outer` object is created."

It then continues and defines `Inner`.

Only later, when you do:

```python
outer = Outer()
```

does `__init__` actually run. At that point, `Inner` already exists as part of `Outer`.

### One important distinction

This:

```python
self.Inner()
```

does **not** mean:

> "Look for an `Inner` object inside `self`."

It means:

> "Look for the `Inner` class available through this `Outer` instance, and create an instance of it."

You could make this even clearer by writing:

```python
class Outer:
    class Inner:
        def show(self):
            print("Inner object belongs to Outer")

    def __init__(self):
        self.inner = Outer.Inner()
```

Here `Outer.Inner()` explicitly means:

**"Create an object of the `Inner` class nested inside `Outer`."**

Then:

```python
outer.inner.show()
```

means:

```text
outer
  ↓
outer.inner
  ↓
Inner object
  ↓
show()
```

So the short answer is: **the position of `Inner` below `__init__` doesn't matter here because the body of `__init__` isn't executed until `Outer()` is called.**
